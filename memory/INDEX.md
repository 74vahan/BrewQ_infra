# Memory — BrewQ_infra

Оглавление. Этот репозиторий содержит backend (FastAPI), веб-панель баристы
(React + Vite), медиа меню и CI/CD (GitHub Actions) с деплоем. Docker,
Terraform и nginx живут в `BrewQ_image`, клиент — в `BrewQ_android`.

### Проверено в Q1 (10.10.2026, сквозная: Android-эмулятор + панель + backend в compose dev)

Стенд: `brewq-dev` (`BACKEND_PORT=18090`), панель `VITE_USE_FAKE_API=false
VITE_API_TARGET=http://127.0.0.1:18090`, эмулятор `miasin_api37`, `adb reverse
tcp:8081 tcp:18090`. Все семь сценариев пройдены; найденные замечания (без багов
контракта, backend не менялся):

- Полный цикл: заказ из приложения появился в панели через ~1,1 с (БД
  `created_at` 21:30:21.76 -> первое появление в DOM 21:30:22.88);
  `NEW -> IN_PROGRESS -> READY -> PICKED_UP` кнопками панели, экран статуса
  приложения следовал за каждым шагом (опрос 5 с), READY-баннер показан один раз
  и после перезапуска процесса не повторился; заказ в истории приложения и в
  «Сегодня» панели.
- Отмена клиентом из `NEW` работает; из `IN_PROGRESS` кнопки в приложении нет, а
  прямой `POST /api/orders/{id}/cancel` даёт `409 ORDER_NOT_CANCELLABLE`.
- Стоп-лист: позиция в корзине -> бариста выключает -> «Оформить» отказывает
  (`409 CART_HAS_UNAVAILABLE_ITEMS`), корзина перечитывается, строка подсвечена
  «Нет в наличии», кнопка неактивна; обратное включение -> флаг пропал. В меню
  (через панель) позиция показывается «Нет в наличии».
- Второй заказ при активном -> `409 ACTIVE_ORDER_EXISTS`, приложение открыло
  существующий заказ, новых заказов не создано.
- en/ru/hy в приложении (меню, карточка, корзина, оформление, заказ, история,
  настройки, READY-баннер) и в панели (очередь, «Сегодня», стоп-лист) — без
  «сырых» ключей, армянские глифы рисуются. `ci/check-i18n.mjs` — 88 x 3.
  `ci/check-cyrillic.sh` — OK для `BrewQ_infra` (255 файлов).
- Замечания низкой важности, подробности в `BrewQ_android/memory/04-toolchain.md`:
  READY-баннер не гаснет сам, когда заказ уже выдан/отменён; открытая корзина и
  меню не обновляются, пока бариста меняет стоп-лист (только при заходе на
  вкладку/потяни-обнови/отказе сервера).
