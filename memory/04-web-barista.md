## Стек и сборка

Версии (пины — в `app/web/package-lock.json`, на 09.10.2026 актуальные
стабильные): React 19.3, Vite 8.3, TypeScript 6.0 (`~6.0.3`), ESLint 10 +
typescript-eslint 8, react-router 7.18, i18next 26 + react-i18next 17,
TanStack Query 5, Vitest 5. Node `>=20.19` (требование Vite 8).

- React + Vite + **TypeScript (strict** + `noUncheckedIndexedAccess`,
  `exactOptionalPropertyTypes`, `erasableSyntaxOnly`) — типы ответов API
  пишутся по `03-api.md` руками в `src/api/types.ts`.
- `react-i18next`, словари `src/i18n/locales/{en,ru,hy}.json`; паритет ключей
  проверяет `ci/check-i18n.mjs` (и в CI, и локально: `npm run check:i18n`;
  принимает каталог словарей и каталог исходников параметрами). Старая копия
  `app/web/scripts/check-i18n.mjs` осталась от F1 и не используется.
- TanStack Query: `refetchInterval: 5000`, `refetchIntervalInBackground: true`
  (вкладка панели часто не в фокусе на планшете у стойки).
- Без внешних CDN и Google Fonts (CSP `'self'`): шрифт — одно семейство
  `BrewQ Sans`, собранное из npm-пакетов `@fontsource-variable/sora`
  (латиница и latin-ext, бренд-шрифт редизайна R5), `@fontsource-variable/noto-sans`
  (только кириллица) и `@fontsource-variable/noto-sans-armenian` (армянский);
  `src/styles/fonts.css` объявляет четыре woff2 с `unicode-range`, браузер берёт
  файл по символу. Лицензия OFL-1.1. **Ловушка:** все четыре `@font-face`
  обязаны иметь один и тот же `font-weight` (`100 800`): браузер сначала выбирает
  набор граней по weight/style и лишь потом применяет `unicode-range`, поэтому
  грань с другим диапазоном (Noto 100–900 при Sora 100–800) вытесняла Sora, и
  латиница молча рисовалась системным Segoe UI. Найдено реальной проверкой в
  Chrome, закреплено тестом `hygiene/sourceRules.test.ts`. **Inline-стили
  (`style={…}`, `<style>`) не используются** — иначе пришлось бы ослаблять
  `style-src 'self'`.
- `npm run build` = `tsc -b && vite build` → `dist/`. На сервер едет только
  `dist/` в `/srv/brewq/web/releases/<sha>/`.
- Dev: `npm run dev` (5173), Vite проксирует `/api` и `/media` на
  `http://127.0.0.1:8081` (переопределяется `VITE_API_TARGET`).
- Проверки: `npm run lint` (ESLint, type-aware), `npm test` (Vitest: разбор
  конверта ошибок, tokenStore, ключи i18n для всех кодов/статусов, форматы),
  `npm run check:i18n`.

## Слой данных и фейк (до готовности backend)

`src/api/barista.ts` объявляет интерфейс `BaristaApi` (`login`, `listOrders`,
`changeStatus`, `listMenu`, `setAvailability`) и реальную реализацию
`httpBaristaApi`. `src/api/fake/` — реализация того же интерфейса в памяти
(демо-меню и заказы, те же коды ошибок, таблица переходов, задержка 120 мс).
`src/api/index.ts` выбирает слой один раз:

- production-сборка — **всегда** реальный HTTP (`import.meta.env.DEV`
  статически `false`, фейк вырезается из бандла; проверено grep по `dist`);
- `npm run dev` — фейк по умолчанию; `VITE_USE_FAKE_API=false` → реальный
  backend через прокси;
- пароль фейкового входа — только из dev-переменной `VITE_FAKE_API_PASSWORD`
  (пусто = подходит любой непустой); пароль баристы нигде не зашит.
  `app/web/.env.example` — пустые значения.

В UI при фейке показывается плашка «Демо-данные».

`src/api/client.ts`: конверт `{error:{code,message,details}}` → `ApiError`;
не-JSON (HTML 502/504), пустое тело, JSON без конверта → `UNKNOWN`; не-JSON
`429` → `RATE_LIMITED`; обрыв/таймаут (15 с) → `NETWORK`; отмена вызывающим
(unmount) пробрасывается как есть; 2xx без JSON → `UNKNOWN`. Коды ошибок —
`src/api/errorCodes.ts` (все из `03-api.md` + `NETWORK`, `UNKNOWN`); для каждого
обязан быть `errors.<CODE>` в трёх словарях (тест + скрипт).

с миниатюрой 56 px (радиус 12), размеры S/M/L чипами с контуром, переключатель
в акценте. Отклонения от плана (по результатам теста контраста):

## Аутентификация

- Экран входа: одно поле «Пароль кофейни» → `POST /api/barista/login`.
- Токен — в `localStorage` с `expires_at`; по истечении или на любой
  `401 BARISTA_UNAUTHORIZED` — токен удаляется, переход на вход. Почему
  `localStorage`, а не `sessionStorage` — `06-decisions.md`.
- Кнопка «Выйти» — удалить токен. `X-Device-Id` панель не шлёт никогда.
- `429 RATE_LIMITED` на входе → «Слишком много попыток, подождите минуту».

## Экраны (F2)

1. **Очередь** (`/`): три колонки `NEW` / `IN_PROGRESS` / `READY`, старые
   сверху (с 48 rem — рядом, на телефоне — друг под другом). Карточка — «билет»:
   крупный `code` (`A-007`, тот же номер видит клиент), `customer_name` если
   есть, «N мин назад · 11:45», перфорация, позиции «название · размер × qty»,
   «Итого» (`total_amd`, формат по локали), кнопки. Опрос
   `GET /api/barista/orders?scope=active` каждые 5 с, в том числе в фоновой
   вкладке. Пустая очередь — подсказка «Активных заказов нет».
2. **Сегодня** (`/today`): `scope=today`, новые сверху, только чтение
   (карточка без кнопок, со статусом и временем), сверху счётчики по статусам.
   Опрос каждые 5 с (только пока вкладка видима).
3. **Стоп-лист** (`/menu`): `GET /api/barista/menu`, группы coffee / tea / cake
   (неизвестная категория — в конец группой «Другое»), строка: картинка
   (`image_url` по относительному пути, при `null` или ошибке загрузки —
   значок категории), имя, размеры, переключатель `role="switch"` «В наличии /
   Нет в наличии» → `PATCH /api/barista/menu/{id}`. Обновление оптимистичное,
   при ошибке откатывается только эта позиция, показывается плашка. Список
   перечитывается раз в 15 с (изменение с другого планшета).

Шапка: переключатель языка en/ru/hy (сохраняется в `localStorage`),
переключатель звука, «Выйти».

### Кнопки заказа

Строятся **только** из `allowed_transitions` (`orders/transitions.ts`):
вперёд — крупная янтарная кнопка («Начать» → IN_PROGRESS, «Готово» → READY,
«Выдан» → PICKED_UP), рядом «Отменить» (→ CANCELLED) с подтверждением в
модальном `<dialog>` (фокус по умолчанию на «Оставить заказ», Esc закрывает).
Кнопки «назад» нет: переход, который не ведёт вперёд по цепочке статусов,
отбрасывается, даже если сервер его прислал; значение, для которого нет
подписи (статус из будущего), тоже. Пока идёт запрос, кнопки карточки
заблокированы (`disabled`, `aria-busy`); после успеха карточка сразу
переезжает в новую колонку (кэш обновляется из ответа, идущий опрос
отменяется), затем идёт перечитывание.

### Ошибки (`notices/noticeErrors.ts`, плашки внизу экрана)

| Ситуация | Реакция |
|---|---|
| `409 INVALID_STATUS_TRANSITION`, `404 ORDER_NOT_FOUND` при действии | списки перечитываются, плашка (янтарная) «Заказ уже изменён. Список обновлён.» |
| `401 BARISTA_UNAUTHORIZED` (любой запрос) | токен удаляется (`barista.ts`), `RequireAuth` ведёт на `/login`, плашки нет |
| `429 RATE_LIMITED`, `INTERNAL_ERROR`, `NETWORK`, неизвестный код | плашка (красная) с переводом по `code`; при опросе — плашка вверху экрана «Нет связи. Показаны последние данные.» (последние данные остаются на экране, опрос продолжается сам и снимает плашку) |
| ошибка первой загрузки (данных ещё нет) | сообщение + кнопка «Повторить» |

## Сигнал о новом заказе

`orders/NewOrderWatcher` смонтирован в `Layout`, поэтому работает на любом
экране (бариста может быть на стоп-листе). `newOrderTracker.ts`:

- первый опрос после открытия панели — базовая линия, сигнала нет;
- сигнал даёт `id`, которого раньше не было **и** у которого статус `NEW`
  (заказ, появившийся уже «в работе», взят другим планшетом); множество
  виденных `id` только растёт — заказ, выпавший из одного опроса и
  вернувшийся, не сигналит дважды;
- сигнал: **звук** (если включён), **подсветка карточки** (метка «Новый» и
  пульсирующая рамка, только `opacity`; при `prefers-reduced-motion` без
  движения), **счётчик в заголовке вкладки** `(2) Очередь · BrewQ` (заголовок
  собирает `ui/DocumentTitle`; сторож только пишет число в `ui/titleBadge`), **объявление для
  скринридеров** (`role="status"`). Любое касание/нажатие клавиши считается
  «увидел» и снимает подсветку и счётчик.

Звук (`sound/chime.ts`) синтезируется WebAudio: два синусоидальных тона
(880 и 1318 Гц, огибающая «колокольчика», ~0,75 с), без файлов и CDN.
**Политика autoplay:** `AudioContext` создаётся только внутри жеста
(`unlockAudio()`): нажатие «Войти», любое касание/клавиша, включение
переключателя звука (заодно проигрывает пример). После перезагрузки страницы
браузер снова блокирует звук, пока не было касания, — тогда под шапкой
появляется плашка «Браузер блокирует звук до первого нажатия» с кнопкой
«Включить звук», а первое же касание где угодно снимает блокировку.

## Фейковый слой (расширенный в F2)

`api/fake/fakeBarista.ts` честно повторяет контракт: статус-машина
(`NEXT_STATUSES`), `409` с `details {from,to,allowed}` при повторном или
обратном переходе, `404`, `401` без токена, порядок очереди (старые сверху) и
«Сегодня» (новые сверху), порядок меню coffee→tea→cake. Меню — копия
`backend/seed/menu.json` (одна позиция без картинки). Рычаги для проверки
(`api/fake/controls.ts`, в dev — `window.brewqFake`; кнопка «Добавить
демо-заказ» в жёлтой полосе):

| Рычаг | Что делает |
|---|---|
| `addOrder()` | «клиент оформил заказ» — новый `NEW` в следующем опросе |
| `advanceBehindUi(id?)` | другой планшет продвинул заказ: клик панели получит 409 |
| `setOffline(bool)` | все вызовы падают `NETWORK` |
| `failNext(code, status)` | один следующий вызов падает (429, 500…) |
| `expireSession()` | следующий вызов — `401 BARISTA_UNAUTHORIZED` |

Dev-сервер `vite.config.ts` отдаёт `/media/*` из `app/media` (в production
это делает nginx), чтобы картинки меню были видны без backend; если файла нет,
запрос идёт в прокси.

## Принципы UI

- Все строки — в i18n (en/ru/hy), включая подписи статусов, размеров,
  категорий и сообщения по каждому `code` ошибки. `message` сервера не
  показывается. Неизвестный `code` → общая формулировка.
- Имена позиций — как пришли (английский).
- Сенсорный планшет: цели нажатия ≥ 44 px (кнопки действий 52 px),
  контраст AA, статус всегда текстом, не только цветом, видимый `:focus-visible`.
- Ошибка сети при поллинге не очищает экран: показываются последние данные и
  плашка «Нет связи».

  колонками, затем виден в «Сегодня» со статусом «Выдан» и верными счётчиками.
- Отмена из `NEW` через диалог подтверждения -> `CANCELLED`, виден в «Сегодня»;
  клиентский `GET /api/orders/{id}` показывает `CANCELLED`.
- 409: заказ продвинут `curl`-ом (`IN_PROGRESS -> READY`), клик «Готово» в
  устаревшей карточке -> `409 INVALID_STATUS_TRANSITION`, плашка «Заказ уже
  изменён. Список обновлён.», карточка переехала в «Готов».
- Стоп-лист: переключатель Latte -> `PATCH /api/barista/menu/4` ->
  `GET /api/menu` отдаёт `is_available:false`; клиентское `POST /api/cart/items`
  на эту позицию -> `409 MENU_ITEM_UNAVAILABLE`; обратное включение
  вернуло `true`. Картинки `/media/menu/*.svg` грузятся.
- i18n: en / ru / hy на очереди, «Сегодня» и стоп-листе — без «сырых» ключей,
  без кириллицы в en/hy и без армянских символов в en/ru.
- Слой данных (`httpBaristaApi`) отдельно прогнан против живого API через
  временный Vitest-тест (удалён): `login`, `listOrders(active|today)` (порядок:
  в очереди старые сверху, в «Сегодня» новые сверху), все переходы,
  `INVALID_STATUS_TRANSITION` (409, `details.from/to/allowed`),
  `ORDER_NOT_FOUND` (404), отмена, `setAvailability`, `MENU_ITEM_NOT_FOUND`,
  `BARISTA_UNAUTHORIZED` (токен сбрасывается). Формы ответов совпали с
  `types.ts` и `03-api.md`.

Замечания (не баги контракта): на этой машине порт 8081 занят чужим
контейнером, поэтому backend поднимался с `BACKEND_PORT=18090`, а Vite — с
`VITE_API_TARGET=http://127.0.0.1:18090`. Один раз за сессию первый клик по
кнопке сразу после поступления нового заказа не дошёл до обработчика (запрос не
ушёл), повторить не удалось (10+ последующих кликов, в т.ч. сразу после
сигнала, отработали с первого раза) — наблюдать на реальном планшете.
